# 常见问题与注意事项

> 这份文档随模块一起发布，讲的是「遇到问题怎么自己解决」，不是功能罗列。
> 控制目录 = 模块配置文件所在的位置（设置页底部会显示实际路径）。

> ## ⚠️ 看不到 `dshxpandh_status` 这些工具？
>
> **重启一次 DSH 引擎**就行，不用新开对话——工具在插件加载时注册，重启后当前会话下一轮就能用。
> 重启后还没有，看第 1 节的两条排查。

---

## 1. DSH 里看不到 dshxpandh_status 这些工具

**重启一次 DSH 引擎就行**：工具在插件加载时注册，重启后重新注册，**正在用的会话下一轮就能看到，不用新开对话**。

**重启后仍然没有，按两条查**：

1. 打开 `dsh-app/diagnostics.md` 的 appErrors 段，找 `cannot get property "tools" without inject`
   —— 有这一行就是插件没声明 `inject`（13.0.1 起已修，旧版必有）
2. 装的可能还是旧插件：设置页点「安装到 DSH」重新释放一份，再重启引擎

**验证**：直接说「用 dshxpandh_status 查一下状态」，能返回模块版本就算通了。

---

## 2. 设置页「DSH 连接」显示未连接

**原因**：心跳由 DSH 里的对接插件写，**每分钟一次**。它只在 DSH 引擎运行时才写：

- DSH 没打开 → 不写
- DSH 被系统冻结 / 后台被清 → 不写
- 插件没装进 DSH → 不写

**这三件事跟插件本身坏没坏无关。**

**解决**：
1. 点「重新检测」——重读一次心跳
2. 还是未连接 → 点卡片打开 DSH，等 10~60 秒再看
3. 一直未连接 → 到设置页点「安装到 DSH」，按提示在终端装插件，然后重启 DSH 引擎

**判定标准**：心跳超过 5 分钟没更新才算断开。

---

## 3. 点「安装到 DSH」好像没反应

**原因**：打开本模块时，插件**已经自动释放**到 `<控制目录>/dsh-plugin/` 了。那个按钮只是重新释放一次（升级后需要时用）。

**检查**：用文件管理器看 `<控制目录>/dsh-plugin/` 里有没有这三个文件：

- `package.json`
- `cordis.patch.yml`
- `lib/index.js`

有就是释放成功了。按钮点下去卡片上会显示「已释放 N 项到 …」。

---

## 4. 插件释放了，但 DSH 里还是没有

**装法**（在 DSH 的终端里跑）：

```
dsh plugin --profile web add <控制目录>/dsh-plugin
```

**装完还有两步**：
1. 到 DSH 的「引擎」页重启引擎
2. **开一个新会话**（旧会话不会刷新工具清单）

**检查是否装上**：

```
grep local-dshxpandh ~/.dsh/profiles/web/package.json
```

有输出就是装上了。

---

## 5. 注入没生效

先分清是哪一层：

| 层 | 怎么用 | 生效条件 |
|---|---|---|
| 脚本层 | 把 `.js` 丢进 `<控制目录>/scripts/` | 3 秒内自动注入所有已登记页面，**不用重启 App** |
| 命令层 | DSH 下发 / 手工投放 | 只对指定包名生效 |

**排查顺序**：
1. 目标 App 在 LSPosed 里被勾选了吗？
2. 勾选之后**重启过那个 App** 吗？（不是重启手机）
3. 打开「调试日志」开关，去「调试日志」卡片点**导出日志** —— 它会直接抓 logcat 写成文件，不用连电脑。
   想看 `script-inject` / `aw-eval-ok` 这类标记，在导出文件里搜即可。
4. 脚本是不是幂等的？页面每次重绘都会重跑一遍，不幂等就会重复插入（内置示例的做法是直接 append style，插多次也无害；
   要防重复就先看一眼元素在不在：`if (document.getElementById("my-style")) return;`）

---

## 6. 隐身开着，DSH 却下发不了命令

这是**设计如此**，不是 bug。

| 情况 | 命令走哪 | 隐身能用吗 |
|---|---|---|
| 有 root | 目标 App 私有目录 | ✅ 能，不碰 /sdcard |
| 无 root | 共享文件 `/sdcard/…/c-XXXX.bin` | ❌ 不下发（隐身要求不留痕） |

**取舍**：要么关掉隐身，要么装 root。

---

## 7. 免 root 环境（Shizuku / LSPatch 之类）

**先说清楚**：Shizuku 自己**跑不了 Xposed 模块**——它给的是 adb shell 权限，没有进程注入能力。

免 root 的唯一形态是 **LSPatch / ShizuPosed** 这类「把模块 patch 进目标 App」的框架。

**本模块已经适配**：

- 命令走「共享文件 + ContentProvider」，**不需要 root**
- 但模块 UI 可能不常驻（patch 模式没有独立 App）
- root 相关功能不可用：读 `/data/adb`、写别的 App 私有目录、`pm install`

---

## 8. 共享命令文件长什么样、会不会被检测

位置：`<控制目录>/c-<8位哈希>.bin`

- **文件名**：目标包名的 SHA-1 前 8 位 —— 扫目录的人反推不出是哪个 App
- **内容**：base64 + XOR 混淆 —— 扫不到明文 `js` 关键词
- **存活期**：模块读完**立即删除**，窗口约一个读取周期（2.5 秒）
- **隐身时**：根本不会写

**要知道的边界**：XOR 密钥在 APK 里，只能挡「扫明文」，挡不住反向。真要防检测，靠的是隐身开关和 root 路径。

---

## 注意事项

1. **不要删 `<控制目录>/`** —— 脚本、配方、能力清单都在那里，删了等于清空配置。
2. **装完模块必须在 LSPosed 里启用并勾选目标 App，然后重启那个 App**（不是重启手机）。
3. **隐身开着 + 没有 root = DSH 下发不了命令**。这是取舍，不是故障。
4. **内置脚本与用户脚本同名时，用户优先** —— 想改内置脚本，放一个同名文件进 `scripts/` 即可。
5. **调试日志打开后，即使隐身开着也会写 logcat** —— 排查完记得关掉。
6. **改版本号只动两个源头**：`AndroidManifest` 的 `versionCode`/`versionName` 与 `texts/description.txt`。编译时 `sync-texts` 会把它们写进 `module.prop`；`version.json`、`CHANGELOG.md`、`HookEntry.VER` 要自己同步。
7. **旧会话看不到新工具** —— 见第 1 节，开新会话而不是重装插件。

---

## 还是解决不了

1. 打开「调试日志」，复现一次问题
2. 抓日志：`adb logcat -d | grep -i dshxpandh > /sdcard/DSHxpandh-log.txt`
3. 带上这几样再问：模块版本、LSPosed 版本、Android 版本、目标 App 包名、日志文件
