# 写注入脚本

脚本放 `scripts/`，`.js` 结尾。同目录建 `<文件名>.off` 就停用。

**改脚本不用重装。** 文件一改，3 秒内自动重注入——不用动 APK、不用重启浏览器、不用碰设置页。

## 零、脚本从哪来

两个来源，**同名时以你自己放的为准**：

| 来源 | 位置 | 能不能改 |
|---|---|---|
| **内置** | 打包在 APK 里 | 改不了内容，只能开关或移除 |
| **本地** | `<控制目录>/scripts/` | 随便改、删、加 |

内置脚本在界面上带「内置」标记，点「移除」只是从列表隐藏（**文件不删**），点「恢复被移除的内置脚本」能找回来。

想改内置脚本的内容：把同名文件放进 `scripts/`，会覆盖内置的版本。

### 删了能回来吗

| | 按钮 | 能恢复吗 |
|---|---|---|
| 内置 | 移除 | **能**，文件在 APK 里 |
| 本地 | 删（点两下确认） | **不能**，真删了 |

本地脚本删之前先备份。

## 一、五分钟上手

```js
(function () {
  if (document.getElementById('x-my')) return;   // ① 做过没有
  var s = document.createElement('style');
  s.id = 'x-my';                                  // ② 唯一 id
  s.textContent = 'a{color:red !important}';
  document.head.appendChild(s);                   // ③ 加上去
})();
```

存成 `scripts/我的.js`，刷新页面。三秒内生效。

三件事缺一不可：**IIFE 包裹**（变量不外泄）、**判断已有**（幂等）、**唯一 id**（下次认得出）。

## 二、两条铁律

这两条不遵守，脚本一定会出问题。所以放在最前面。

### 铁律一：必须幂等

脚本会被执行**很多次**——页面每重绘一次、每 3 秒兜底一次。重复执行不能产生副作用叠加。

**判断"做过没有"的三种方式**：

```js
document.getElementById('x-my')        // 元素还在（跨刷新可靠）
window.__myDone                        // 全局标记（刷新就重置，只能防同一轮）
document.querySelector('[data-x-my]')  // 属性标记
```

**绝对不要写**：

```js
alert('hi');                        // 每 3 秒弹一次，手机没法用
location.reload();                  // 无限刷新
document.body.innerHTML += '<div>'; // 每轮追加一份，页面越来越长
setInterval(fetch, 1000);           // 定时器叠加，越跑越多
```

### 铁律二：效果会被冲掉，必须保活

现代网页不停重建 DOM。你加的样式或元素会被覆盖。

**监听变化**（推荐，省电）

```js
function apply() {
  if (document.getElementById('x-my')) return;
  var s = document.createElement('style');
  s.id = 'x-my';
  s.textContent = 'a{color:red !important}';
  document.head.appendChild(s);
}
apply();
new MutationObserver(apply).observe(document.documentElement, {
  childList: true, subtree: true
});
```

**定时补刀**（简单，但要防叠加）

```js
if (window.__myTimer) clearInterval(window.__myTimer);
window.__myTimer = setInterval(apply, 1500);
```

## 三、怎么确认跑成功了

写完立刻能验证，不要凭感觉。

### 办法一：改标题（最快）

```js
document.title = 'OK-' + document.querySelectorAll('a').length;
```

地址栏立刻变化。**一眼看出脚本执行了、页面上有多少个候选元素**。

### 办法二：加边框（最直观）

```js
document.body.style.border = '10px solid red';
```

边框不容易被页面样式覆盖，比改颜色可靠。

### 办法三：控制台

```js
console.log('MY-SCRIPT');
```

```bash
adb logcat | grep -i "MY-SCRIPT"
```

模块的隐身不影响网页自己的 console，那是两回事。

## 四、没效果时的排查顺序

**先分清是哪一层**，这是最省时间的一步。

### 第一步：标题变了吗

| 结果 | 说明 | 往下查 |
|---|---|---|
| **标题没变** | 通道问题，脚本压根没跑 | 见 4.1 |
| **标题变了但页面没变** | 脚本跑了，是选择器或效果问题 | 见 4.2 |

### 4.1 通道问题

按顺序问自己：

1. 那个 App 在 LSPosed 作用域里吗
2. 作用域改完，**重启过那个 App** 吗
3. 页面是 WebView 渲染的吗（原生界面改不了）
4. 脚本文件是不是被 `.off` 停用了
5. 文件 mtime 变了吗（`touch` 一下强制重注）

### 4.2 脚本问题

1. 选择器选得到东西吗（用第三节的办法数一数）
2. 是不是被页面的 `!important` 覆盖了
3. 是不是加上了又立刻被冲掉（加 MutationObserver）
4. 是不是在 iframe 里（见第六节）

## 五、选择器：标红为什么常失败

这是最容易踩的坑，单独一节。

```css
html { filter: invert(1) }   /* 根元素，什么页面都生效 */
a    { color: red }          /* 只匹配 <a>，页面不用 <a> 就没反应 */
```

**反色是"作用于容器"，标红是"匹配元素"**。前者不挑结构，后者挑。

### 现代网页的链接写法

| 写法 | `a{}` 能选到 |
|---|---|
| `<a href>` | ✅ |
| `<div role="link">` | ❌ |
| `<span onclick>` | ❌ |
| `<a>` 但被 `color:#333 !important` 覆盖 | ❌ |

### 推荐写法

```css
a, [role="link"], [href], area, [data-href] {
  color: #e91e63 !important;
  text-decoration: underline !important;
}
```

### 再宽就要付出代价

```js
document.querySelectorAll('*').forEach(function (el) {
  if (getComputedStyle(el).cursor === 'pointer') {
    el.style.setProperty('color', 'red', 'important');
  }
});
```

长页面上几千个元素，**会卡**。而且 `cursor:pointer` 会误伤按钮、菜单、图标。除非必要别用。

## 六、常见坑分类

按成因分三类，遇到问题先想是哪一类。

### 6.1 结构类：CSS 够不到

**iframe 是独立文档**

父页面的 CSS 管不到 iframe 内部。反过来说，父级已经反色时，iframe 里再反一次会**双重叠加抵消**——表现是"某块区域死活不变"。

判断：`if (window.top !== window.self) return;`

**但这招要小心**：有些站点（百度首页就是）的**主内容本身在 iframe 里**，一判断"不是顶层就退出"，整页都不生效了。**用之前先确认主内容在哪一层**。

**独立渲染层**

有些区块自带 `filter` 或 `isolation`，形成独立渲染层，父级的 `filter` 管不到。百度顶部 header 就是这样：主体反色了，header 还是白的。

只能单独挑出来处理：

```js
document.querySelectorAll('header, [class*="head"]').forEach(function (el) {
  el.style.setProperty('filter', 'invert(1) hue-rotate(180deg)', 'important');
});
```

但这是在猜结构，站点改版就失效。

**Shadow DOM**

选择器进不去影子根，要逐个 `shadowRoot` 手动补。

### 6.2 效果类：加上了但看着不对

**图片反两次才是原色**

```css
html       { filter: invert(1) }   /* 全反 */
img, video { filter: invert(1) }   /* 再反回来 */
```

只反 `html` 不反图片，人脸会变负片。忘了这步会以为"反色坏了"。

**被 `!important` 覆盖**

页面自己的 `color: #333 !important` 会盖掉你的普通声明。你的也要加 `!important`，并且选择器权重不能更低。

**加上了立刻被冲掉**

页面重渲染。加 MutationObserver。

### 6.3 交互类：多个脚本打架

**两个脚本互相干扰**

标红 + 整页反色同时开，链接在反色后又变成别的颜色。**不是 bug，是叠加**。

**调试时一次只开一个**，能省很多困惑。

**定时器叠加**

脚本重注入时旧定时器还在。用全局引用兜：

```js
if (window.__myTimer) clearInterval(window.__myTimer);
window.__myTimer = setInterval(apply, 1500);
```

## 七、性能代价

| 做法 | 代价 |
|---|---|
| `setInterval` 每 1.5 秒 | 页面一直有定时器在跑，耗电 |
| 遍历 `document.querySelectorAll('*')` | 长页面几千个元素，会卡 |
| `MutationObserver` 监听整个文档 | 页面频繁变化时回调很密集 |
| 每轮发网络请求 | 3 秒一次，一天上万次 |

**能用 CSS 解决的别用 JS 遍历。** CSS 由浏览器引擎优化，JS 遍历是你自己扛。

## 八、完整流程

给某个站加效果，按这个顺序走：

```bash
# 1. 先只验证通道
cat > /sdcard/DSHxpandh/scripts/我的.js <<'EOF'
(function () { document.title = 'PROBE-OK'; })();
EOF

# 2. 打开目标页面，看地址栏
#    没变 → 先解决通道（作用域、重启），别往下走
#    变了 → 继续

# 3. 写真正的效果，加幂等判断
# 4. 加保活（MutationObserver）
# 5. 关掉其他脚本，单独调试
# 6. 确认没问题再开别的
```

**先验证通道，再写效果。** 跳过第一步直接写复杂脚本，出问题时分不清是哪一层——这个坑我踩过。

## 附：脚本互相影响的实测例子

同时开「链接标红」和「整页反色」：

- 只开标红 → 链接粉色
- 只开反色 → 整页黑底，链接跟着变暗色
- 两个都开 → 链接先被标粉，再被反色，最终是**另一个颜色**

不是谁覆盖谁的问题，是两套样式叠加后的必然结果。
